## Trae / Workbuddy 连不上 GitHub 的原因

这类 AI IDE 连接 GitHub 走的是 **GitHub OAuth API**，不是 git clone。常见原因：

### 1. Token 过期或权限不足
```bash
# 测试你的 GitHub Token 是否有效
curl -H "Authorization: token YOUR_TOKEN_HERE" https://api.github.com
```

**解决：**
- 去 [GitHub Settings → Developer settings → Personal access tokens](https://github.com/settings/tokens)
- 生成新的 Token，勾选 `repo`、`read:user`、`user:email` 权限
- 在 Trae/Workbuddy 中重新填入新 Token

### 2. 工具内需要重新登录
- **Trae**: 设置 → GitHub 集成 → 重新授权
- **Workbuddy**: 清除缓存后重新登录 GitHub

### 3. 代理冲突
如果工具配置了 HTTP 代理但和 GitHub API 不兼容：
- 检查工具的代理设置
- 尝试关闭代理直连测试

### 4. 防火墙/安全组放行
虽然 curl 能通，但某些工具可能有自己的网络栈。确保：
- 端口 443（HTTPS）已放行
- 没有 DDoS 防护拦截了 API 请求

### 一、背景与现状

目前检查检验项目的**注意事项**在系统中存在多处维护的情况：
- **医技海纳系统**：部分注意事项在此维护
- **自助开单系统**：部分注意事项独立维护

这种分散维护模式导致以下问题：
1. **数据不一致风险**：同一项目的注意事项在不同系统中可能不同步
2. **维护成本高**：修改注意事项需同时在多系统操作，易遗漏
3. **患者体验差**：自助开单时展示的注意事项与医技执行要求不一致

### 二、需求描述

**核心目标**：实现检查检验项目注意事项的**统一维护、一处修改、处处同步**。

**具体方案**：
1. **统一维护入口**：所有检查检验项目的注意事项仅在**医技海纳系统**中进行维护和管理
2. **接口自动获取**：**自助开单系统**通过调用医技海纳系统提供的接口，实时获取注意事项数据
3. **数据一致性保障**：建立数据同步机制，确保两端数据始终一致

### 三、预期效果

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| 数据一致性 | 可能存在差异 | 完全一致 |
| 维护效率 | 多系统重复操作 | 单一入口维护 |
| 错误率 | 人工同步易出错 | 接口自动同步 |
| 扩展性 | 新增项目需多处配置 | 新增即同步 |

### 四、技术要求

1. 医技海纳系统提供**注意事项查询接口**（RESTful API）
2. 接口返回格式标准化，支持按检查检验项目编码查询
3. 自助开单系统对接该接口，实现数据自动获取
4. 建议增加**缓存机制**（如 Redis），降低接口调用频率
5. 接口需具备**容错处理**，当医技海纳系统不可用时，自助开单可降级处理

### 五、实施计划建议

1. **第一阶段**：医技海纳系统开发注意事项查询接口
2. **第二阶段**：自助开单系统对接接口，移除本地维护逻辑
3. **第三阶段**：数据迁移与校验，确保历史数据完整性
